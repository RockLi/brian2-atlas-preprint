# 周期运动挑战：先移除单帧位置捷径

新方案的 schema 是 `flywire-periodic-motion-v1`。它用于下一批独立的训练和评估；不能把它的准确率与旧的非环绕刺激直接合并。当前增加的是刺激生成器、数学约束与像素诊断，还没有运行这套刺激的全图仿真或训练新的方向读出。

## 为什么随机起点还不够

旧方案把轨迹中心限制在显示中心附近。向右运动从左侧开始，向左运动从右侧开始，上下运动也对应不同的起点区域。即使 fit、validation、test 的轨迹 seed 严格分离，单帧位置也可能解释方向标签。这样的划分能检验随机轨迹泛化，却不能单独证明读出利用了运动。

将中心相位均匀采样到整个周期平面，可以使每种方向的首帧、末帧位置在总体分布上相同，但有限样本仍可能失衡。因此模块区分两种用途：

- `movie(kind, seed, travel=.8, phase=(0, 0))`：轻量的单相位生成器。新的 seed 给出均匀相位；只有总体分布保证，没有有限样本严格保证。
- `iter_orbit(seed, travel=.8)`：用于正式挑战的完整相位轨道。同一 seed 下所有相位必须同时保留，并整体进入一个数据分区。

## 图像与运动定义

- 48 × 48，40 帧，每帧 10 ms，灰背景 0.5，对比度 0.8。
- Gaussian 宽度均匀采样在 0.10–0.16，亮暗极性随机；同一独立 seed 的全部相位和四个方向共用这些参数。
- 显示空间为周长 2 的二维环面；基础中心相位均匀采样于 `[-1, 1)^2`。
- Gaussian 使用周期最短距离，光斑越界后从对侧继续出现。它不是自然视野边界、遮挡或真实视网膜模型。
- 显示 y 向下增大。右移的 x 正向变化，上移的 y 负向变化。左移/下移直接复制右移/上移的逐帧倒序，所以对向刺激逐像素精确互为逆序。
- 保留旧显示坐标 `linspace(-1, 1, 48)`，使已有双线性 hexel 采样的标定仍适用。环面上的 -1 与 +1 是同一点，因此首末行/列重复一个边界位置；这是明确的显示约定，不是额外的视觉角度标定。

## 有限样本端点平衡

设行程为 `d`，端点相对轨迹中心的偏移为 `d/2`，环面周长为 2。将 `d/4` 写成最简分数 `p/n`，展开 `n × n` 个中心：

```
center(i,j) = base_phase + (2i/n, 2j/n) mod 2
```

每个中心都生成四方向。首帧和末帧只是将中心的某一个整数索引加上或减去 `p`。索引循环平移是同一格点集合的置换，因此每种方向的首帧图像多重集完全相同，末帧也完全相同。

默认 `d=.8` 给出 `p=1, n=5`：25 个中心 × 4 方向 = **100 个视频 / 独立 seed**。宽度、极性及相位偏移必须在整个轨道共享，否则上述图像多重集等价不成立。代码先对整数索引取模，再计算浮点坐标；端点特别使用这些规范坐标，避免数学相等却浮点舍入不同。测试使用图像字节 SHA256 计数比较，不只比较坐标或像素均值。

在完整、等权的轨道中，只接收首帧（或只接收末帧）的任意确定性分类器准确率都恰为 25%：每个相同的输入图像对应等量的四种标签。该结论不涵盖两个端点的联合输入；两帧间的位移本来就携带运动信息，也不涵盖不完整轨道、视频元数据、网络跨 trial 遗留状态或将标签混入随机背景。

代码限制 `d/4` 的精确十进制分数分母不超过 20，避免意外生成庞大轨道。`.4` 和 `1.2` 都需要 `10 × 10 × 4 = 400` 个视频 / seed。这个成本必须计入速度泛化实验。变化行程、帧数和帧时长是不同干预，不能都简称“速度变化”。

## 已执行的数据诊断

`test_motion_challenge.py` 的 6 项测试通过，覆盖精确倒序、像素范围和重复周期边界、跨边界速度符号与恒定速度、端点多重集、同组参数与静态分类、参数拒绝行为。

另外，新的 4,096 个 seed 生成了 16,384 个首帧。只使用最强像素位置的静态规则得到 **24.683%**。这只是一次 Monte Carlo 检查，不是“所有模型都只能达到随机水平”的实验证明。更强的保证来自完整轨道：额外 8 个 seed 的各方向首帧与末帧图像多重集均逐字节一致；测试还覆盖了行程 `.4`、`.8`、`1.2`。

结果保存在 `brian2-rust/validation/flywire-vision-implementation-audit/motion-challenge-diagnostic.json`。可复现命令：

```sh
PYTHONPATH=brian2-rust/experiments python -m unittest flywire_vision.test_motion_challenge -v
PYTHONPATH=brian2-rust/experiments python -m flywire_vision.motion_challenge \
  --output brian2-rust/validation/flywire-vision-implementation-audit/motion-challenge-diagnostic.json \
  --start 900000 --seeds 4096 --travel .8
```

## 下一批训练如何接入

1. 建立新的研究目录和协议，记录本 schema、源文件哈希、已锁定的模型哈希与完整轨道 seed 划分。不要改写旧研究的结果或 producer。输入调用现有 `encode_variant`，因为图像值域、形状与显示采样约定仍兼容。
2. 分配 fit / validation / test 时，以 seed 的整个轨道为单位；`phase_index` 不能作为独立划分单元。`balanced_orbit_seeds` 可以在每个分区选取亮暗各半的独立 seed；各分区仍须显式检查集合无交集。若同一 seed 用于不同速度或背景，相关的全部版本也必须归于同一个分区。
3. 先做小规模开发屏蔽诊断，锁定候选后再生成完整的新测试轨道。8 fit、4 validation、8 test 独立 seed 在默认行程下已需 2,000 次原生仿真，且 test 的统计独立样本只有 8 组；不能因有 800 个测试视频就报告过窄的置信区间。是否扩大预算应先看开发轨道中的运动/静态差距。
4. 在真实下游活动上比较：全时序读出、首帧复制 40 次、末帧复制 40 次、时间顺序打乱、整段倒序、时间求和、标签打乱，以及不经过连接组的直接输入读出。所有 trial 必须完整重置，背景随机数不得依赖标签，训练和验证不得读取新测试特征来筛选细胞或调参。端点静态神经对照的预测还应逐输入一致；若同像素静态刺激得到不同活动，应优先审查复位与背景种子。
5. 初始保留当前 gain=32、固定连接组作为基线。需要进一步提升时，在开发轨道比较当前正负亮度输入与因果帧差输入，以及不同时间池化/细胞数；选择依据应包括运动优于静态和跨条件表现，而不只是一个开发集最高分。使用独立测试轨道一次性验收。
6. 速度、空间相位、背景分别设明确的留出条件，并补充组合变化。周期均匀相位已经覆盖整个显示平面，但它与自然场景的位置泛化不同。背景纹理、真实遮挡和非周期边界应是单独的新挑战；不得把环面中的越界重现解释成遮挡记忆。

完整轨道只排除了单个端点静态位置这个特定捷径，仍不能证明果蝇通路具有结构优势。要回答连接组本身的贡献，还需在同一批视频上加入输入直读、统计匹配重连和目标通路消融。
