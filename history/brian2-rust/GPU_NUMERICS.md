# GPU 数值模式与已验证边界

Metal 与 CUDA 必须显式选择 `numeric_mode="float32"`。这表示接受后端声明的
单精度计算模式，不保证与 CPU `reference-f64` 或另一 GPU 后端逐轨迹相同。
公开结果以 f64 数组返回，也不能恢复计算中已丢失的精度。

## 周期更新的时钟语义

`run_regularly` 按 CodeRunner 自身的时钟触发，但表达式中的 `t`、`dt` 沿用
所属 NeuronGroup 或 Synapses 的时钟，和 Brian2 NumPy/reference 一致。随机数的
计数器仍使用触发时钟的 tick；不能用所属时钟替换随机流坐标。

跨时钟读取 `t` 时，GPU 使用经过验证的整数时钟换算，并保持原来的主机 f64
调度与 epsilon 合并规则。规划器会检查本次运行内所有参与时钟的共同网格、
舍入误差和整数溢出边界；无法证明一致的网格会在编译前明确拒绝，提示缩短运行
区间或使用精确的公度时钟。单时钟模型及不读取 `t` 的周期更新不受此项检查影响。

## 阈值与塑性

浮点误差很小，也可能改变 `v > threshold` 的真假。一个脉冲时间改变后，循环连接、
延迟和 STDP 会继续放大轨迹差异。长时程实验中已保留 f64 略高于 1、f32 恰好等于
1 的反例。见 [长时程边界证据](execution-plan-evidence/long-stdp/README.md)。
在新增 [低活动率对照](execution-plan-evidence/activity-stdp/README.md) 中，f32 与 f64
都产生 45,542 个脉冲，平均频率相同，但完整坐标有 35 个额外、35 个缺失，首个差异
位于 tick 684、神经元 3213。相同的总数或平均频率也不足以证明轨迹兼容。

因此性能验证同时检查状态、权重及完整脉冲坐标。仅通过浮点数组容差不足以计入
性能排名。不能通过给阈值统一加 epsilon 来保证与 f64 等价。

类型转换、运算顺序或调度实现错误仍须修复，不能归入精度差异。例如此前常量指数
优化错误忽略类型转换，已修复并验证，见
[指数转换证据](execution-plan-evidence/power-casts/README.md)。

`exprel` 也已修复两个求值问题：近零处的减法消差，以及先算 `exp(x)` 导致
`exprel(90)` 这类有限 f32 结果误报溢出。现在使用近零多项式与大参数分段计算，
真实结果溢出仍报错。M3/L4/A100 的 539 点网格和 HH 完整数组复验通过；HH 相对
原 f64 的部分状态/轨迹检查仍失败，不能把函数修复等同于轨迹兼容。
见 [exprel 范围与精度验证](execution-plan-evidence/exprel-range/README.md)。

## 数学函数的设备间舍入

当前 `pow` 等数学函数不承诺不同 GPU 与 CPU libm 逐位相同。M1 Ultra 本轮在
动态或带类型转换的指数上观察到 `(-2)**(-1)`、`(-2)**(-33)` 和 `(-2)**(-2)`
与 CPU f32/M3 不同，最大相对误差约 `1.1921e-7`；指数转换、符号和有限值判定正确。
这不是之前忽略类型转换的代码生成错误，也不能据此改变用户的指数或阈值。

幂函数回归沿用原有浮点函数 `rtol=2e-5`，采用更严格的 `atol=0`，并额外精确检查
符号、零、单位结果和指数奇偶性。可证明常量的乘法特化仍在这些 dyadic 输入上逐位检查。
原先 6 个 M1 失败是新增测试误要求与 libm 逐位一致，修正后的四设备回归均通过；
原始失败、实际数组与独立复核见 [M1 收尾证据](execution-plan-evidence/m1-current/README.md)。
完整模型的脉冲坐标与性能准入门槛没有放宽，函数误差仍可能放大为轨迹差异。

## 极小数值：保存下来不等于参与算术

f32 最小正规数为 `2^-126`（约 `1.175e-38`），最小正 subnormal 为 `2^-149`
（约 `1.401e-45`）。本轮在 Apple M3、NVIDIA L4 和 A100 上分别验证了正负值的
复制、乘以 0.5、乘以 `2^24`，以及 `v > 0` 阈值；覆盖独立 population 与空连接 DAG。

- M3 Metal：复制能保留 subnormal 位模式；上述乘法和比较符合将 subnormal 操作数
  或结果归为带符号零的参考。复制后的非零值也可能无法触发 `v > 0`。
- L4/A100 CUDA：当前 `--ftz=false` 等编译选项下，上述操作符合 IEEE f32 渐进下溢
  参考，包括 subnormal 参与放大后重新成为正规数。
- CPU f32 控制组：本轮同样符合 IEEE f32 参考；仍可能与 f64 下溢结果不同。

这不是所有数学函数的统一承诺。共享 `b2_exp` 实现显式将 subnormal 输出归零，
包括 CUDA；`--ftz=false` 不会覆盖源码中写出的归零逻辑。本轮没有验证全部算术操作，
本轮 M1 Ultra 的最新回归已包含这套边界测试并通过其已声明检查；其他 Metal GPU 仍未覆盖。

这六个 M3 用例的浮点数组均通过原有容差，但脉冲均不符合 IEEE f32 参考，因此
**仍不满足现有 portable f32 性能资格**。归零参考用于解释观察结果，不是新增运行
模式，也不替换或放宽性能检查。本轮没有产生性能排名或修改内核。

完整原始数组、源文件身份和独立位编码复核脚本见
[subnormal 验证证据](execution-plan-evidence/subnormal/README.md)。

## 如何选择

需要保留现有 f64 轨迹时使用 CPU reference-f64。使用 GPU 时显式选择 f32，并对
目标模型的时长、脉冲与塑性轨迹做验证；尤其不要只比较最终状态或脉冲总数。
如果模型依赖 subnormal 运算，上述 CUDA 测试提供了有限范围的证据，Metal 当前
不提供与该 IEEE f32 参考等价的保证。任何重标度或软件浮点方案都需要单独证明和
测量，当前没有通过隐藏重标度改变用户模型。
