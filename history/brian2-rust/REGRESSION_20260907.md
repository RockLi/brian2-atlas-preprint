## 实际改动

1. 将生成的缓存 normal/binomial RNG 包装函数标为 `#[inline(always)]`，使编译器能够在调用点进一步优化分支和缓存访问。随机数算法、计数器身份和调用语义保持原样。
2. 对通用 plasticity pre pathway 使用 `#[inline(always)]`；post pathway 保持 `#[inline(never)]`。选择依据来自独立的 pre/post/both 对照，不按模型名称写特例。
3. FlyWire 的 Git 来源信息改为可选：源码归档中没有 `.git` 或 Git 可执行文件时记录 `null`，避免模拟成功后仅因读取来源信息而失败。
4. 修正空 neuron-state 阶段的计时测试：只有参数、没有状态更新的阶段可能在一个时钟精度内完成，因此允许计时为零。保留所有阶段非负、实际事件阶段大于零和完整状态一致性断言。

升级生成器后应重新构建 AOT 制品：`write_compatible_instance()` 按生成源码哈希检查二进制兼容性，本次内联属性改变了该哈希。这个检查继续保持严格；本轮没有修改 checkpoint 数据格式。

## 性能方法

- 核心门：全部 24 个单线程场景，每场景 5 次；多线程覆盖 CUBA 100k、COBAHH、PoissonInput，共 27 的 18 个配置和 23 的 21 个配置。
- 同实例对照：基线和候选都从**同一绝对路径的 `main.rs`** 新鲜编译，只撤销/启用上述三个内联选择；保持 crate 名、编译参数、实例、线程数相同。8 个负载分别预热一次，再交替执行 5 次；每次验证完整 `results.bin` SHA-256 相同。额外提取 Mach-O/ELF 代码段哈希，辨认机器码未变化的场景。
- 优化选择与确认分离：先用 3 次样本选择 RNG/塑性内联方案，另用 7 次样本探索确认；最终净收益以本节明确控制源码路径的新鲜编译对照为准，不混用早期探索数据。
- 对第一轮任一后端 min/max spread 超过 15% 的线程配置，按“波动”而非“加速比”选择，独立复测 9 次，保留两轮结果。
- 原生 loop、原生进程 wall time、Python 构建及首次运行分别统计。原生 loop 加速不自动等于端到端加速。
- PD14/Brunel 在同一后端固定线程数的重放要求字节一致；跨后端随机流不同，不将这一检查误称为跨后端逐字节等价。

## 对替换旧 backend 的含义

这轮验证针对“已支持语义能否保持正确，并跨 ARM64/x86-64 避免性能退化”。它不能单独证明所有 Brian2 API 可替换，也不改变既有长时程 LK 生物学验证的解释。

本轮不重新运行 2,610 秒学习与自发活动实验；固定输入一致性、完整 backend 测试、同实例逐字节对照用于约束本次代码生成优化。科学复现、任意模型兼容性和全生命周期端到端成本仍须各自验收。

下一阶段应优先分解 CUBA、COBAHH 的串行段、worker dispatch、事件路由和内存带宽成本，再选择并行优化。当前扩展数据能证明“加线程收益递减”，尚不能仅凭该表认定某个单一根因。23 本轮只覆盖一个 NUMA 节点；跨 NUMA/96 核能力需要独立实验。
