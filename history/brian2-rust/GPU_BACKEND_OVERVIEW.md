# GPU 后端当前阶段

当前阶段：**Metal/CUDA 后端已完成本阶段交付。**
它们已经接入 Brian Device 使用流程，并有真实 GPU 的结果证据。
固定验收矩阵、性能对照和交付结论见 [阶段性交付报告](GPU_DELIVERY.md)。
M1 最新回归已闭环；M3/L4/A100 收尾检查通过。全部 Brian2 兼容和所有规模占优不属于本阶段承诺。

## 本阶段 Goal 与完成标准（2026-09-09 明确）

**交付支持范围明确、结果可信、在代表性中大型网络上有可重复收益的 Metal/CUDA
后端，并完成 Brian2CUDA、Brian2GeNN 和直接 GeNN 的可复核对照。**

本阶段按以下三项验收：

1. 明确功能范围、精度契约和已知限制，完成真实 Metal/CUDA 上相关功能与生命周期
   回归；支持契约内的已知正确性错误必须解决。显式 f32 不要求与 f64 逐脉冲一致，
   但必须报告差异，且不能用精度不同解释违反自身 f32 契约的错误。
2. 以已有 ring、随机稀疏和延迟 STDP 证据整理固定验收矩阵，明确模型输入、精度、
   设备和计时范围。保留中大型模型的重复测量、小规模/低活动率边界以及三类外部
   对照；原版、修正版和失败项分别报告，不要求战胜每个对手，不把串行参考当作多核上限。
3. 关闭该矩阵内尚未完成的检查，逐项记录通过、失败或明确的范围排除，整理使用说明、
   复现证据和交付报告。不能通过删除失败项把自研后端的正确性门槛变成通过。

**小模型 GPU 慢于 CPU 可以接受，不阻塞完成。** 自动回退 CPU、跨输入自动调优、
所有功能组合的穷举验证、GPU 拓扑初始化和持续主机/内核微优化均列入后续工作，
除非它们直接阻塞上述验收。每轮实验后不自动扩大验收矩阵；新增门槛须对应支持范围内
具体的正确性风险或新约定的需求。优先收敛已有验证缺口；优化若没有可重复且有实际
意义的端到端收益，记录结果后暂停，不为追求某个小场景占优持续投入。

完整状态表中的历史“尚未完成”条目属于长期路线图，不能全部解释为本阶段交付阻塞项。

## 数值与兼容边界

GPU 使用显式选择的 `numeric_mode="float32"`；CPU 原有 f64 契约继续保留。
验证同时使用独立参考计算和编译后的 f32 控制组，检查完整脉冲坐标、状态、权重
及声明的监控数组。f32 与 f64 的阈值附近差异可能改变脉冲时刻，并进一步改变
塑性轨迹；这些差异必须报告，不能用修改阈值 epsilon 来掩盖。

独立参考验证也已发现并修复 GPU/CPU 镜像共同存在的错误，例如常量指数优化忽略
类型转换、把应为 `x**0` 的表达式变成 `x**-1`。该修复已在 M3、L4、A100 及
AOT 验证，详见 [指数转换修复](execution-plan-evidence/power-casts/README.md)。

最新边界测试还确认：M3 Metal 可保存极小 subnormal 数值，但乘法/阈值比较仍可能
将它们当作零；本轮 L4/A100 对复制、乘法及比较符合 IEEE f32 参考。浮点容差通过
不代表脉冲一致，现有性能检查保持不变。范围与建议见 [GPU 数值说明](GPU_NUMERICS.md)。

部分限制来自冻结的 B2IR v1，例如独立 StateMonitor 时钟/非 start 槽位；另一些
属于后端支持范围。需要扩展 IR 的功能与需要补充 GPU 实现的功能分别记录在完整
状态表中。当前测试也尚未覆盖全部被接受模型的生命周期组合。

## 外部性能比较

已经运行 Brian2CUDA、直接 GeNN 和 Brian2GeNN 的版本固定对照。比较返回完整结果，
分别报告准备/编译与重复执行成本，并只给通过对应数值门槛的实现计入性能排名。
Rust f64 与 GPU f32 精度不同；CPU f32 控制组用于数值对照，不代表优化过的多核 CPU。

原版 GeNN/Brian2GeNN 的失败与明确标注的修正版分别保留。修正版的同步屏障或
结果读取优化不能冒充原版结果。较早的 IF、循环网络、HH 与 STDP 证据也不应跨
模型或跨云端分配直接组合成一个总加速倍数。

最新规模对照将固定出度 8 的环形 STDP 扩到 16,384 个神经元、131,072 条连接，
每次模拟 256 个 tick。较大模型默认完整执行中位数为 M3 Metal 67.2 ms、L4 CUDA
34.8 ms、A100 CUDA 32.6 ms；同机串行 Rust f64 参考分别为 85.7 / 216.0 / 181.8 ms。
我们的四种 GPU 策略全部与编译 CPU f32 数组一致。原版直接 GeNN 在较大模型上于
L4/A100 分别多出 1 / 6 个脉冲并有状态偏差，已排除；通过的变体明确单列。
408 份完整结果、3,264 个字段复核通过。它说明特定模型扩大后已有 GPU 收益，
不能推广到任意拓扑或多核 CPU，详见 [规模对照](execution-plan-evidence/population-scale/README.md)。

最新的密集 STDP 对比（1,024 个神经元、131,072 条连接）中，我们的 CUDA 完整
执行中位数为 L4 299 ms / A100 408 ms，可选 prefix 策略为 225 / 320 ms；
同轮 Brian2CUDA 为 1,584 / 2,178 ms，原版 GeNN 为 912 / 1,222 ms。
本机 M3 Metal 为 930 ms。我们的 GPU 结果通过独立与编译 CPU 两套 f32 检查。
这表明已有适合 GPU 的模型；此前稀疏长时程模型仍暴露明显开销，不能推广为
所有网络都有同样收益。修正版 Brian2GeNN 在本轮权重检查失败，未计入排名。
完整条件和证据见 [密集 STDP 对比](execution-plan-evidence/dense-stdp/README.md)。

最新内部配对实验进一步复用 CUDA 的主机脉冲记录区。长 STDP 模型的完整执行
中位数从 L4 204 → 172 ms、A100 249 → 210 ms，五轮配对均改善，GPU 计算时间
基本不变。代价是执行器存活期间保留记录数组；该模型为 128 MiB。本轮 M3 没有
稳定收益，因此 Metal 默认保持原方式。这组数据不用于更新上面的外部后端排名，
详见 [记录区复用证据](execution-plan-evidence/host-reuse/README.md)。

新增静默/低活动率对照（同为 4,096 个神经元、32,768 条连接，1 秒模拟）中，
CUDA 完整执行中位数为 L4 25 / 36 ms、A100 33 / 42 ms。静默场景仍没有超过
各自的 Rust f64 参考；M3 Metal 两种场景均慢于 Rust f64。低活动率场景的原版
GeNN 在 L4 数值检查失败，已排除；修正版单列。这里比较的是完整重置到结果的
时间，包含外部适配器的 load/unload 等成本，不是纯 GPU 内核速度。
详见 [活动率对照](execution-plan-evidence/activity-stdp/README.md)。

新增的显式 CUDA 多线程块常驻 DAG 已通过 L4/A100 正确性验证，但三个配对案例的
完整执行中位数均退化：L4 约 8–15%，A100 约 4–11%。一次启动仍需 4,096 次全局
同步，GPU 计时本身也更慢，因此默认策略不变。这条实验路径不能计作性能收益；
详见 [协作执行实验](execution-plan-evidence/cooperative/README.md)。

后续同一内核的七种线程块数量实验也已完成：L4/A100 各 23 项原生测试通过，
所有完整数组通过 f32 对照，但没有任何测试配置超过默认分块 Graph。
这说明本轮尝试的线程块数量调整未解决问题；下一步检查能否安全融合相邻突触阶段，
减少执行与同步步骤。详见 [线程块配置实验](execution-plan-evidence/geometry/README.md)。

相邻 pre/post 突触阶段融合也已完成一轮实现与验证：本机 Metal/CPU 47 项通过，
L4/A100 各 58 项通过，126 份完整基准结果与未融合 CPU f32 一致，事件总数也通过
独立计算。但三台设备三个案例全部变慢；密集案例 L4 313 → 638 ms、A100
415 → 876 ms、M3 706 → 1282 ms。当前实现将 post 边更新串行放入目标线程循环，
减少一次 dispatch 并没有弥补失去的边并行度；具体瓶颈尚未单独剖析。
因此 `gpu_synapse_fusion` 默认关闭，详见
[突触融合实验](execution-plan-evidence/synapse-fusion/README.md)。

最新改动会在运行起点的 pending 队列为空时省去历史队列遍历，实时延迟事件仍由
history ring 处理，边并行和调度次数保持不变。126 份完整基准结果及事件总数检查
通过。收益较小且不一致：L4 中位数改善 0.2%–2.5%；A100 静默/低活动率约改善
1%，密集案例约慢 0.9%；M3 密集案例约改善 7%，另外两例没有改善。部分时间范围
重叠，不能据此声称稳定通用加速。首轮云端的测试平台选择错误及修正复验均保留，
详见 [空 pending 队列特化](execution-plan-evidence/empty-pending/README.md)。

并行前缀现在能处理只在前缀内部使用的浮点、整数和布尔临时变量，仍不增加中间
缓冲区。带临时值的密集 STDP 配对实验中，M3 667 → 592 ms、L4 319 → 240 ms、
A100 417 → 286 ms，约改善 11% / 25% / 31%，每台设备五轮均改善；静默和低活动率
案例略慢。因此现有 `gpu_synapse_prefix=True` 继续显式启用、默认关闭。
本轮扩大的是可优化的程序范围，不代表此前已经能拆分的无临时变量程序又获得同样
加速。真实 Brian 临时表达式的分段与恢复也已在 Metal 补验。
详见 [前缀临时变量验证](execution-plan-evidence/prefix-locals/README.md)。

续跑携带 pending 延迟事件时，现在也能在证明每条边每个 tick 最多一次事件、且
不与实时事件重叠后保留并行前缀。新增一个有大小上限的只读位图；不能证明安全时
仍走原有投递路径。M3/CPU 26 项测试通过，L4/A100 各 37 项通过，126 份完整续跑
结果通过独立 f32、编译 CPU f32 和事件总数检查。密集续跑中位数分别为 M3
719 → 657 ms、L4 311 → 237 ms、A100 437 → 301 ms，五轮配对均改善；静默和
低活动率中位数仍更慢，默认继续关闭。这里测量已准备执行器的重放，初始规划及
位图构造成本不在重复测量内。详见 [pending 续跑优化](execution-plan-evidence/prefix-pending/README.md)。

可变突触的目标端投递新增显式 `gpu_synapse_sparse=True`，按源/延迟分组展开实际
事件，并按原顺序消费目标队列；历史 pending 独立处理。三台设备各 42 项测试通过，
126 份完整续跑结果通过双重 f32 与事件总数检查。静默场景 CUDA 中位数改善约
31% / 34%（L4 / A100），低活动率在三台设备改善约 6–7%，五轮配对均更快；
密集场景却慢 11–19%，因此默认继续关闭。M3 静默测量波动较大，不宣称稳定收益。
额外队列和分组数组在这组模型中约占 672 KiB / 1.57 MiB，初始规划不计入重放时间。
详见 [稀疏塑性投递](execution-plan-evidence/target-sparse/README.md)。

稀疏目标队列又完成了限量写入实验：目标一旦必须回到密集扫描，就不再写入后续
队列项。M3/CPU 34 项、L4/A100 各 45 项测试通过，完整结果保持一致，但密集
重放在三台设备均慢约 2–3%，因此生产仍保留原队列算法。实验入口和失败收益
记录保留；27 个最终计划与已测试版本逐一匹配，详见
[队列限量写入实验](execution-plan-evidence/sparse-saturation/README.md)。

CUDA 原子读取现已在支持的工具链/架构上使用设备范围的 relaxed load，旧工具链
分支保留原实现。L4/A100 的 PTX、SASS 和整数位模式验证通过，但完整执行收益
很小且不一致，不能计为稳定加速；四种组合的 168 份完整结果均通过 f32 检查。
扩大回归还发现并修复了稀疏队列同名导入遮蔽 EventMonitor 缓冲区函数的问题，
原先即使关闭队列也可能规划失败。修正后本机 CPU/Metal 50 项、L4/A100 各
75 项测试通过，原始失败及修正复验均保留。详见
[CUDA 原子读取与监控回归修复](execution-plan-evidence/atomic-load/README.md)。

最新组合验证已将稀疏目标队列、并行前缀与延迟塑性、多时钟、整数/链接状态、命名事件、
监控及续跑恢复一起测试。M3、L4、A100 各 20 项通过、12 项跨平台跳过；离线复核
78 组配对快照、2,934 个数组字段，并验证 CUDA 实际缓冲区/内核复用。只有新增指数
迹变量使用声明的 f32 容差，最大绝对误差约 1.91e-7；其余数组和同后端恢复继续精确
比较。四个原有默认模型逐字节不变。这轮未改后端或默认策略，也没有新增性能结论。
详见 [组合策略与生命周期验证](execution-plan-evidence/composed-policies/README.md)。

最新位图投递实验使用原始 rank 顺序的位图替代当前事件队列排序，保留 pending 的重复
事件与顺序，并保持相同缓冲区和调度。M3、L4、A100 各 58 项通过、31 项平台跳过；
126 份完整重放结果通过独立 f32/事件计数检查，且与原编译 CPU-f32 数组精确一致。
密集案例中位数分别为 866→545、342→218、493→309 ms，改善约 36–37%；低活动率
改善约 22% / 11% / 13%，每台设备五轮配对均更快。静默场景收益很小或退化，因此
现已可用 `gpu_synapse_sparse="bitset"` 显式选择，原 `False` 默认和 `True` rank 队列
保持不变。这组内部对照不更新外部后端排名。
详见 [位图投递实验](execution-plan-evidence/target-bitset/README.md)。

正式入口补齐了计划校验、EXPLAIN 标记和跨策略复用验证。本机 65 项通过、33 项跳过；
L4/A100 在完整计算验证后各补验一项 Linux 平台预期，综合覆盖同为 65 / 33。
两轮之间后端源码不变；30 个默认计划保持一致，9 个正式位图计划保留此前实测内核。
详见 [正式位图选项验证](execution-plan-evidence/bitset-api/README.md)。

Brian2GeNN 密集 STDP 的权重偏差现已定位：其事件时间是 double，生成代码将迹变量
与 double 指数结果相乘后才写回 float32；我们的 f32 控制则先舍入衰减因子。
独立重放精确复现两台 GPU 的原始权重和迹变量。在同一个生成模型上仅增加因子转换，
L4/A100 各三次原生运行均通过完整 f32 检查，权重与参考精确一致；原版本各三次仍复现
偏差。未放宽容差，未改我们的后端，也未更新外部排名；这是需单独标注的比较器变体。
详见 [Brian2GeNN 精度路径诊断](execution-plan-evidence/brian2genn-precision/README.md)。

后续已将该精度变体作为 `brian2genn-f32-factor` 接入正式对照流程。L4/A100 各完成
预热和五轮随机顺序测量，新变体均通过完整 f32 检查。完整执行中位数为 1,941 / 2,707 ms，
同轮我们的 CUDA 为 300 / 459 ms，可选 prefix 为 226 / 281 ms，Brian2CUDA 为
1,644 / 3,227 ms，原版 GeNN 为 951 / 1,401 ms。A100 的部分外部后端波动较大，
完整范围保留；这些包含重置、进程/加载和结果回传成本，不是纯内核速度。
原调度适配版本仍因权重失败而排除。48 项本机回归和 128 份结果 / 1,024 个数组字段的
离线复核通过。详见 [精度变体同轮对照](execution-plan-evidence/brian2genn-factor/README.md)。

位图投递现已缩小实际缓冲区：每个目标只分配 `ceil(入度/32)` 个字，以只读偏移表替代
未使用的计数数组。密集模型单 pathway 从 528,384 字节降至 22,360 字节，节省约
494 KiB；占全部声明数组约 1.93%，不能等同于整个进程内存下降 96%。M3/L4/A100
各 44 项测试通过，126 份基准结果通过完整 f32 和事件检查。CUDA 耗时变化较小且范围
