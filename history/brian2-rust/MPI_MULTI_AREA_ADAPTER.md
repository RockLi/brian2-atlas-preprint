# Multi-Area Model：官方参数、脑区归属与编译资源门槛

接续 `df5c3d33` 的分布式 fixed-total 建图。当前适配器是 Brian2 的离散时步实现，
**尚未通过 NEST 的时序、活动统计及论文结果验收**，不能作为完整科学模型复现。

## MPI 实现

`build_distributed_plan` 和 `write_mpi_project` 新增 `population_owners`：按 B2IR population
顺序给出 rank 整数，或 `None` 保留原来的平均连续分区。由此可以把同一脑区的所有人群
放在一个 rank，也可以混用整个人群归属与分片。归属写入不可变执行计划及哈希。

静态边路由、二进制 CSR、procedural 入边、神经元/子组状态、脉冲、监控及最终 Gatherv
均遵守同一归属。支持非顺序归属和完全空 rank，保持全局随机身份和结果位模式。
`run_regularly(..., when='synapses')` 现可在本地神经元上执行直接 Poisson 输入。

两项存储优化：

- procedural 空入边投影的源索引数组为零容量，调度跳过空投影的源行访问；报告实际
  `rank_csr_offset_bytes`。完整模型原本每 rank 复制约 1.48 GiB 源索引，现只保留本地非空投影。
- 如果突触运行期表达式不使用 RNG，在权重与延迟初始化后释放全局边身份数组。
  运行期随机突触继续保留原始身份。

`tools/multi_area_capacity.py` 按脑区入边数做确定性的贪心分配，给出必要数组容量，
**它不是作业准入器**。完整参数下最重 rank 的 `target u32 + weight f64 + delay usize + CSR`
下限：2 ranks 约 226.09 GiB，4 ranks 113.11 GiB，8 ranks 56.74 GiB。
这些数字排除队列、监控、神经元初始化、编译器与分配器，不能据此启动完整模型。

## 模型适配与保护

`examples/mpi_multi_area.py` 从已固定的参数快照创建脑区子集，使用电流型 LIF、
相等时间常数的指数突触电流、官方初始电位分布/阈值/复位/不应期。
Brian2 默认方法选择在本次模型中为 exact；dt=0.1 ms。
未模拟脑区明确定义为 `hom_poisson_stat`，10 Hz，官方平均权重、入度和距离延迟。
同权重、同延迟 bin 的独立 Poisson 输入按叠加性质合并，不使用 Bernoulli 或 Gaussian 近似。
外部默认连接延迟采用 1 ms；跨 NEST 的首个输入 bin、阈值与不应期边界仍需验收。

准备器在创建神经元前限制 100,000 个神经元、100 million 递归突触、1,000 ticks。
这只是该试跑工具的限额，不是后端容量结论。现有全局显式数组预算与默认 procedural
每 rank 10 million 入边限额仍然生效。

Linux 制品位于 `/data/brick2/brian2-mpi-region-20260907`。
每个运行/编译服务沿用实际已验证的 MemoryMax=2 GiB、SwapMax=0、CPUQuota=200%、
AllowedCPUs=0–7、TasksMax=64、120 秒工作负载超时与整个 cgroup 清理。
23/24 运行前均重新确认约 1 TiB MemAvailable、独立数据盘空间和无遗留测试服务。

V1/V2，N=K=0.01：3,540 个神经元、105,973 条递归突触、137 个投影；V1→rank0，V2→rank1。
初次 opt-level=3 Rust 编译约 10,500 行源码，超过 120 秒被终止，cgroup 峰值
1,875,943,424 bytes（约 1.75 GiB），oom_kill=0。C 桥接已完成，残留 Rust 目标文件
确认实际进入优化编译。该结果是受限编译超时，不是主机内存耗尽。

编译 API 新增显式 `opt_level`（0..3，默认仍为 3），记录到 `build.json`。
曾用级别 1 在相同 120 秒限制下尝试，也超时，峰值约 1.30 GiB，没有 OOM。
MAM 工具默认保持级别 3，不能用降低编译级别冒充同配置加速。
随后合并初始化内核，但 120 秒仍不足；继续将严格匹配 `target += immutable_weight` 的
突触事件处理合并为共享内核。FIFO 顺序、统一延迟的源批处理及逐边延迟语义保持不变，
复杂/随机/条件表达式仍使用原路径。

用户指出 2 GiB 过于严格后，下一档提高为编译 8 GiB、CPUQuota=400%、300 秒；
双节点每台一个 rank，运行服务 8 GiB。仍禁用 swap、检查主机余量并使用硬超时。
此前结果只是初始保守额度下失败，不能据此推断服务器无法完成编译或仿真。

## 整个目标人群归属时的本地建图

当 `population_owners[target]` 是确定 rank 时，该 rank 直接按完整投影的抽样编号生成
CSR，其他 rank 返回空数组。各 owner 可以并行构建自己的投影，不再逐投影调用 MPI
计数/转发，也不再保留 16-byte 临时边记录或排序。
两遍抽样用稳定计数定位恢复 reference 的 source-major 边编号，复杂度 O(E_owned+N_source)。
全局边身份目前仍临时存储，用于保持权重、延迟及运行期 RNG；不能宣称所有初始化
峰值都已降低。分片人群继续使用原分布式抽样路径；混合两种路径的 collective 顺序保持一致。

运行报告增加 `construction`，并据真实执行路径记录抽样工作量；整个人群归属时，
只有 owner 报告该投影的全部抽样数。默认累计每 rank 入边预算不变，分配前检查。
本次完整 60 项 MPI 回归，以及单独的混合路径/累计预算中止测试通过。

下一档已准备 N=K=0.1 的 V1/V2：35,494 个神经元、10,604,386 条递归连接、150 个非零投影；
生物时间 100 ms。两个 rank 的完整入边分别为 4,761,595 / 5,842,791，均低于默认 10 million
入边预算，基础边数组约 95.2 / 116.9 MB（不含队列、构建和监控）。
编译与运行的正式结果另行归档，准备成功不代表该档已通过双节点验证。

## 连续阈值的批量脉冲交换

MPI 调度生成器现在合并连续、相同时钟、不同事件向量的生产节点。任何非生产节点
（包括监控、突触处理和复位）、时钟变化、重复事件向量或 MPI i32 总容量边界都会结束
当前批次，先完成交换再执行下一节点。每个原始节点的运算顺序不变，事件历史在交换后、
任何消费者之前记录。单机 CPU 路径保持原来的即时记录行为。

网络包使用人群前缀偏移编码神经元编号，一次 Allgather 长度和一次 Allgatherv 内容后排序、
按人群解码。保留本地所有权、全局范围、唯一性与容量检查。缓冲区按批次神经元总数增长，
当前 35,494 神经元模型接收缓冲约 277 KiB；它不随突触数增长。
计划 `exchange_nodes` 表示逻辑上需要同步的事件生产者，不是实际 MPI 调用次数。
运行报告的 `spike_exchange_strategy` 和 `exchange_calls_per_rank` 给出实际策略和计数。
这仍是每 tick 的同步 Allgatherv，尚不是区域订阅或异步 lookahead。

同一 V1/V2、N=K=0.1、100 ms 模型在 23/24 交替运行新旧版本各三次：

| 指标 | 逐人群交换 | 批量交换 |
| --- | ---: | ---: |
| 交换次数 / rank | 16,000 | 1,000 |
| 仿真与记录中位数 | 3.8712 s | 2.5847 s |
| 三次耗时范围 | 3.6272–3.8849 s | 2.5732–2.6029 s |

同配置下中位耗时减少 33.23%，约 1.50× 加速。这里的比较对象是本项目上一版 MPI 实现，
不是 Brian2 或 NEST 的最佳单机实现。三个新版试跑的 rank 峰值 RSS 约 105.5 / 125.9–128.6 MiB，
与旧版基本持平；不将小幅分配器波动解释成存储优化。
六次运行结果哈希均与独立 reference 一致，首次新版完整文件逐字节比较也通过。
18 个运行服务（6 controller + 12 proxy）均验证 8 GiB、400% CPU、SwapMax=0、无 OOM。
新版编译 230.99 秒，峰值 1,998,209,024 bytes，仍未解决多投影编译成本。

验证：最终完整 MPI 回归 64 项通过；CPU/执行计划 22 项和 21 subtests 通过。
新增边界测试覆盖插入监控与无监控零延迟投递。自定义 on_pre slot 尚不受当前前端/MPI 支持，
本次没有扩宽其能力范围；早期测试配置被该门槛拒绝，最终用支持范围内的调度完成验证。

## 1.70 亿连接与新增节点的本地存储

## 投影表与保序循环：编译复杂度优化

`write_mpi_project(..., compact_projections=True)` 提供可选的投影压缩生成路径；
MAM CLI 对应 `--compact-projections`。同构 fixed-total 投影共享加载函数、配方表、
队列表和报告循环；仅把连续且布局相同的加法投影合并为有序循环。它不改变计划、
输入分片、随机身份、浮点相加顺序或标量内核。布局不适合时保留原始生成路径，
manifest 的 `projection_compaction` 记录实际采用情况。默认不开启此实验性选项。

四脑区 N=K=1 已在相同四台 Linux 机器重新通过逐字节参考校验。编译 10.32 秒，
整个作业峰值 529 MiB；之前的 O1 编译记录为 170.43 秒。新运行初始化 45.08 秒、
仿真/记录 31.17 秒，337,355 次 spike 和 1,071,780,053 次突触投递均与参考一致。
rank 峰值仍约 9.3–12.0 GiB，各节点 32 GiB 保护额度内无 OOM。
这里证明的是编译成本改善和数值等价，运行时间差异不足以证明稳定加速。

完整 32 区的生成源码从 24,434,849 缩到 7,405,363 bytes。Rust 1.86 的类型检查和
借用检查在 121.26 秒内完成，作业峰值 3.14 GiB；此前配方表版本的借用检查在
300 秒时仍未结束，峰值 16.2 GiB。实际 O1 编译仍在 Rust 1.86 和隔离的 1.98.1
工具链上触及 600 秒额度，热点已进入 LLVM PHI 节点优化。进一步拆分初始化和
输出函数仍在实验；完整 32 区尚未运行，也未证明服务器硬件资源不足。
